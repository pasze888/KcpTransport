# 回退会话迁移：单一地址表，换网即掉线重连

状态：Accepted（2026-10-26）。对应规格 [#22](https://github.com/pasze888/KcpTransport/issues/22)。**部分取代** [ADR-0008](0008-per-session-event-loop.md)：它的「每会话一条 loop」亲和仍然成立，它的「会话号的第二个索引（#21）」一节（含三条实现约束与两条已知行为）自本篇起作废。

这是一次**主动回退**，不是缺陷修复：双索引没有 bug，它只是不值这个价。[#21](https://github.com/pasze888/KcpTransport/issues/21) 完成后不到一天就回退，记在这里是为了让后来人看到判据，而不是只看到代码里少了一张表。

## 为什么回退

1. **需求证据为零。** #21 上线后，迁移路径没有任何真实触发记录。「从未触发」目前仍是推断而不是证据——但没有证据这件事本身是信号，而成本是确定的：多一张表、多一条分支、多一个测试、多一处跨 loop 写。
2. **成本不对称，而且它是个伪造面。** 迁移是全仓唯一一处跨 event loop 的写（ADR-0008 因此把「全部共享可变状态」从一条改写为三条）。更要紧的是，`UkcpServerChannel.dispatch` 的迁移分支**不校验 `sn`**：任何 24 字节以上、携带已知 conv 的包都能把会话抢到自己的地址上——链路上的观察者可以定向踢人，也可以把回包引流到自己的端口。这个面不是实现疏忽，是「按会话号找回会话」这条设计的直接推论：会话号由客户端选定且不校验，一旦拿它当查找键，任何知道这个数字的人就参与了一起路由决策。
3. **收窄触发条件不划算。** 迁移判断发生在喂内核之前，攻击者可以构造任意 `sn`（包括 `sn == 0`），所以「只让首包触发迁移」既不解决伪造，又要多养一条分支和一个测试。

## Considered Options

- **保留双索引，给迁移加 `sn` 门槛**：加一道闸要写一个测试、养一条分支，而伪造面没消失——`sn` 同样是攻击者可填的字段。否决。
- **保留双索引，但把会话绑到 IP 而不是 ip:port**：能挡住跨 IP 的抢夺，代价是同一 NAT 后面的两个客户端被视为同一来源，把「撞号才出事」降级成「同一出口就出事」。仍然要靠会话号路由，仍然要靠客户端填的号码做查找键。否决。
- **只删迁移，不补「同端口换号重连」**：改动最小，但会留下一个永久卡死：同一 ip:port 换了 conv 发首包时，地址命中即喂内核，内核按包头 conv 校验不符返回 `-4`（`kcp/base/Kcp.java:727-729`），包被丢而会话不重建，客户端只能等 30 秒读超时。这条是 #22 的**必补项**，与回退是同一次改动。否决。
- **单一地址表 + 补「同端口换号重连」（选定）**：路由键退回唯一的远端地址，地址不变即快路径；地址命中但包头 conv 与会话 conv 不一致、且 `sn == 0` 时，关旧建新。与 kcp-go `sess.go:1187-1199` 同构。

## Consequences

- **退化声明（玩家可见）。** NAT 或路由器的端口重绑定**不再被吸收**：地址未命中就按陌生对端处理，非首包丢弃，客户端重传直到原版 `ReadTimeoutHandler(30)` 收场。玩家表现从「卡一下」退化为「换网、切 Wi-Fi↔4G 后掉线，重连」。这是 #22 明确接受并记录的代价，不是待修缺陷。
- **换号重连仍然成立。** 同一 ip:port、新 conv、`sn == 0` 时关旧建新。没有这一条，「重连」在固定端口上会永久卡死（见上面「只删迁移」的推断）。
- **共享可变状态回到一条。** 父 `UkcpServerChannel` 只剩一张 `ConcurrentHashMap`，跨 loop 的写只剩「child 在自己的 loop 上关表」这一处；每个会话的远端地址字段也不再有写方，因此升成 `final`——票面写的是「去掉 `volatile`」，`final` 比「去掉 `volatile`」更准：没有写方就不该允许写，编译期就锁住。ADR-0008 的「全部共享可变状态」清单就此缩回它原本的一条。
- **ADR-0008 的三条实现约束全部作废，其中第 3 条是反转。** 当初写的是「`remoteAddress()` 不能返回 `super.remoteAddress()`，因为 `AbstractChannel` 缓存首值」。迁移取消后地址不再移动，缓存即正确值，覆写改回 `return (InetSocketAddress) super.remoteAddress();`（与同类的 `localAddress()` 同形；不能整段删掉，`UkcpChannel` 声明的是 `InetSocketAddress` 返回类型）。第 2 条「删表按 value 不按 key」不再是被迫的时序补丁，而是对并发关闭的普通防御，保留。
- **conv 本身不动。** 回退的是「用 conv 路由」，不是 conv：线上 24 字节头、`createChildChannel` 的 conv 参数、`UkcpServerChildChannel.conv()` 全部保留，内核仍按包头 conv 校验（不符返回 `-4`），**不同来源**的多会话隔离仍依赖它。边界要说清：同一 ip:port 上的两个 conv 不是「共存」，而是「后来者重建」——所以「靠 conv 在同一个 UDP 端口上分开多条连接」只对不同的 ip:port 成立（`smokeRebind` 的 P1 用的就是两个端口）。
- **机检负控。** `./gradlew smokeRebind` 从「证明迁移」翻转为「证明不迁移」，**七**个控制固定下来：①变端口不迁移（新端口收不到 ACK、会话数与会话实例都不变）；②多会话按各自 conv 独立建立（两个来源、两条会话）；③陌生 conv 的非首包仍被丢弃；④同地址同 conv 的普通包不重建（同一实例）；⑤同地址新 conv 的非首包被丢弃（不建不毁）；⑥同地址新 conv 的首包重建会话；⑦三个会话把地址表填到 3，关掉父通道后清空到 0。`verifyNoSettlingWindow` 随之退役——它守的是「迁移不许长冷却期」，迁移没了，这条守护没有对象。

  第 ⑦ 条走的是父通道 `doClose` 遍历关子会话这条真实路径。**「旧会话 30 秒内被 `ReadTimeoutHandler(30)` 关闭后移除」只有散文，没有机检**：内核的 dead-link 检查被注释掉（内嵌 `Kcp.java` 里那行 `//if (segment.xmit >= deadLink)`），静默对端永远不会被服务端察觉，所以「关掉客户端等它自己消失」在这个代码库里不可观测。要机检它得起真实 MC 客户端——这一条留给实机验证，不假装冒烟覆盖了。
- **不回退的部分。** 每会话一条 loop 的亲和（ADR-0008 主体）不受影响；本篇只摘掉那张 conv 表和依赖它的一切。

## 实施中与票面的偏离

票面写「关旧建新」，实现是**先建新、再关旧**（`UkcpServerChannel.dispatch`）。顺序调换的理由是关闭的落点：旧会话的 `close()` 由父 loop 发起、实际在旧 child 自己的 loop 上执行；若先关，地址键在异步关闭落地之前仍指向一条正在死的会话，中间会短暂出现「表里有两条、其中一条不可用」。先建则新会话立刻占住地址键（`put` 覆盖），旧会话随后按 **value** 自删，既盖不掉新会话、也不留幽灵条目。效果与票面一致（会话数稳定为 1），顺序不同，记在这里，不让代码和文档各说一套。

另两处偏离都是收紧而非放宽：一，父通道在**喂内核之前**就把 conv 不符的非首包丢掉，而票面的必补项只要求「`sn == 0` 时关旧建新」——提前丢弃与内核自己返回 `-4` 等价，只是省掉一次内核输入；二，远端地址字段升成 `final`（见上）。票面的「三 commit 拆分」也未兑现：本次会话的 `.git` 只读，代码与文档都留在工作区未提交，拆分退化为「代码一次、文档一次」。

## 已知行为（不是缺陷）

**回包永远只发原地址。** 票面验收里「变端口不迁移……回包只发新地址」与「不迁移」自相矛盾；按票面其它三节（新增负控 2/3、退化声明）实施，正确行为是旧会话的回包仍只发旧地址，新端口在新会话建起来之前收不到任何东西。这是票面的一处措辞缺陷，已记录。

**重建可以被旧对端抢回去。** 判定只看包头 `sn == 0`，于是一个仍在重传自己首包的旧对端（`sn` 仍是 0、conv 是旧的）会再次触发重建，把刚建好的新会话关掉；同一 ip:port 上两个活跃 conv 因此能来回重建。#22 之前不存在这条（那时第二个对端只是被忽略）。要堵它得记住「这个 (地址, conv) 重建过」，那是又一个状态加又一个测试，#22 用来否决「收窄触发条件」的同一条判据在这里同样适用，所以记为已知行为。触发它需要在路径上伪造受害者的源 ip:port（不需要知道 conv，本判定只读地址与 `sn`）——这比 #21 的伪造面窄（那边只需要知道 conv），但方向相反：现在任何人都能让一条会话被重建。

**同一 ip:port 上的两个 conv 不能共存**（见上文 conv 那条）。
